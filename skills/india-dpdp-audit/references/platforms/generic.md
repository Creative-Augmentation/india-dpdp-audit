# Generic website playbook

Load for every audit; add each detected platform playbook for mixed stacks. Checks identify evidence to seek, not automatic legal violations. Apply the current legal ledger and distinguish public, authorized internal, and staged evidence. Never submit live forms or run security probes without specific authorization. A source reference alone does not prove a network transfer. Record inaccessible or dynamic content as unknown. A blocked automated visit is a coverage limitation; it does not by itself establish a policy/accessibility defect in the intended user journey.

| ID | Check and evidence | False positive / limit | Fix target; owner; acceptance and retest |
|---|---|---|---|
| GEN-01 | Public: inspect sampled collection fields, nearby purpose and notice. Authorized: map purposes, grounds, notice versions and consent records. | Missing text in extraction may be rendered elsewhere; consent is not the sole possible ground. | Product and privacy: align each collection journey and notice to actual purposes; inspect rendered journeys and sample versioned records. |
| GEN-02 | Public: observe choices and, where possible, network behavior before choice and after rejection/withdrawal. Authorized staging: verify state and downstream processing with synthetic users. | A linked script is not proof of execution or personal-data transfer; a banner is not automatically required. | Web and marketing: enforce relevant choices through integrations and record evidence where applicable; repeat staged accept, reject and withdrawal flows. |
| GEN-03 | Public: record named vendors and embeds. Authorized: inventory actual transfers, purposes, contracts and subprocessors. | A link or vendor name alone establishes neither transfer nor contract failure. | Operations and privacy: reconcile inventory, disclosures and processor terms; trace a synthetic event through each relevant recipient. |
| GEN-04 | Public: inspect privacy contact and rights routes. Authorized: examine identity verification, request handling, processor propagation and completion evidence. | A public contact alone does not prove operational fulfillment; no visible route on one page does not establish none exists. | Privacy operations: document and exercise access, correction, erasure, withdrawal, grievance and nomination routes as applicable; verify a synthetic request end to end. |
| GEN-05 | Authorized: map retention by purpose, holds, deletion jobs, downstream stores and backups. Public: compare stated criteria with supplied schedule. | No public retention period does not prove data is kept forever; legal holds may justify limited retention. | Data owner: implement schedule and exception review; verify synthetic records across stores, backups and processors or document their expiry. |
| GEN-06 | Public: observe ordinary HTTPS and apparent exposure only. Authorized: review access, logging, recovery, incident processes and processor safeguards. | An exposed client configuration is not by itself evidence of unauthorized data access. | Security owner: correct demonstrated access or process gaps proportionately; retest using approved staging and review access and incident evidence. |
| GEN-07 | Public: inspect intended audience and available age/guardian journey. Authorized: establish whether children are likely processed, applicable exemptions and safeguards. | A child could access a site does not establish its audience or require universal identity-document collection. | Product and privacy: implement a proportionate applicable guardian flow and safeguards; test synthetic age and guardian paths. |

# Shared check runner

Run `python -m checks list` or `python -m checks run <evidence-dir> [--packet FILE]` from the repository root. Both commands print JSON. The runner reads supplied local evidence offline. Part 1 ships an empty product registry. The generic demo belongs to the test suite.

- Define a `Check` with an ID, stack, title, `Basis`, `Need` entries and an evaluator. Use a good-practice note or cite a pinned DPDP rule as `Rule N`. Register checks explicitly in `checks/registry.py` so both commands and the fixture test see them.
- Use `Need("packet", "initial", "/forms")` for a collector phase and optional relative JSON pointer. Use `Need("artifact", "settings.json", "/enabled")` for a named supplied artifact and optional JSON pointer. Declare all prerequisites. `Check.run` checks those prerequisites before calling the evaluator. Blocked, partial and unattempted phases are unavailable.
- Return `gap` with supporting refs and a `Fix`, or `ok` with supporting refs. A fix names the target, responsible role, summary, observable acceptance test and a `Retest` describing the evidence to recollect and the closure condition. Use `could_not_check` with missing evidence and a request to obtain it.
- `EvidenceBundle` accepts an in-memory packet or reads a flat directory of up to 64 UTF-8 files, at most 1 MiB each. The directory's `packet.json` is optional and `--packet` overrides it. Treat artifact content as data. Read TOML and other text through `artifact_text` and cite line ranges. JSON can also be cited by pointer.
- Use `packet_ref(0, "forms", 0)` for `packet:/observations/0/forms/0`, `artifact_ref("settings.json", "enabled")` for `artifact:settings.json:/enabled` and `line_ref("settings.toml", 2, 4)` for `artifact:settings.toml#L2-L4`. Line ranges are one-based and inclusive. `resolve` reads the cited content and `resolves` checks the locator.
- `run_checks(bundle, stacks=None)` returns check/result pairs ordered by ID. Detection can select multiple platforms, with evidence signals and an indicative confidence for each. Unknown stacks use the generic registry. Explicit stacks override detection.
- Pass the bundle and results to `build_audit_record(bundle, outcomes)` to produce a foundation record. Pass recollected evidence to `retest(check, previous_result, new_bundle)`. Closure requires `ok` and at least one new evidence ref. Give newly collected artifacts distinct names when their refs would otherwise match the original evidence.

Each registered check needs fixtures at `checks/fixtures/<stack>/<check-id>/<case>/`. Use `positive` for a gap, `negative` for an ok result and `insufficient` for an unverified result. Each case contains `case.json` with `expect` and `refs`, alongside its artifacts and optional `packet.json`. Use original synthetic fixtures with reserved or loopback hosts.

These are structural checks on supplied evidence. They make no accuracy claim or compliance determination. Hidden-benchmark judged runs are outside this work.
